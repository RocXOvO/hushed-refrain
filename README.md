乐评寻踪支持网易云音乐和 QQ 音乐。网易云任务按数字 UID 精确匹配公开评论，可扫描用户来源或对单曲做时间分片；QQ 任务将数字 QQ、个人主页 URL 或 EncryptUin 解析为规范目标，按完整 EncryptUin 精确匹配，可扫描指定单曲或公开“我喜欢”歌曲。桌面客户端、本地 Web 控制台和 CLI 共用断点续跑、多出口、实时结果与结构化日志能力。

> [!IMPORTANT]
> 请只在合法、合理的场景中查询公开数据，尊重用户隐私、平台规则与请求频率。该工具不能绕过私密的听歌排行或喜欢列表，也不保证找到用户的全部历史评论。

## 功能一览

- **顶部双平台工作区、内部四视图**：顶部在网易云与 QQ 音乐工作区之间切换；网易云“用户来源 / 单曲并行”与 QQ 音乐“单曲顺序 / 公开喜欢”相互隔离，不会串任务、结果或日志。
- **统一紧凑导航与可缩放布局**：网易云和 QQ 音乐共用相同的紧凑图标导航；窗口横向或纵向缩放时，工具栏和浮动面板会重排或互斥，长表格与面板内容在各自区域滚动，不会因平台切换挤占主工作区。
- **歌名搜索**：单曲任务可输入歌名或歌手并从候选列表选择，不需要先去官网查找歌曲 ID；纯数字 ID 仍作为高级兼容入口。
- **EncryptUin 单次解析实验**：可手动输入裸 EncryptUin、严格允许的 QQ 音乐官方个人主页链接，或十进制 QQ / 内部 ID 候选。链接携带 EncryptUin 时仅做本地提取与离线解码；数字候选只在显式点击后联网解析。联网在代理池或显式代理存在时 fail-closed，只有用户明确勾选 `allowDirect` 才直连，绝不静默回退。API 响应和 renderer 内存会持有完整候选，但默认不会写入可见 DOM 或剪贴板；只有显式显示或复制才可见。19 位结果只标为“QQ 音乐微信内部 ID（wxuin 候选）”，不是微信号。不提供批量导入、枚举或反查。
- **双平台视觉**：网易云与 QQ 使用独立主题，切换时由左下到右上的轻量粒子扫场过渡；减少动效模式会立即切换。
- **断点续跑**：歌曲游标、分片进度、请求数和冷却时间都会原子化写入 JSON 检查点；Windows 文件短暂占用会自动重试，并可从已完整写入的遗留临时文件恢复。
- **自适应页级调度**：Worker 每次只处理一页；用户来源只剩一首歌时也会把未读时间范围拆给多个出口，减少扫描后期的并发长尾。
- **独立出口代理池**：可勾选一套或多套 Clash Verge 配置合并优选，或导入其他 HTTP/HTTPS 代理。
- **实时可观测**：中央“并行歌曲”页面展示正在扫描的歌曲、活跃/配置 Worker，以及每首歌已读评论数和进度条；主区持续显示总进度、累计请求、命中、实时评论与最近 10 秒实际评论读取速度。
- **完整结果 PDF**：实时结果可随时导出为 A4 报告；运行中的任务会冻结导出开始时已经完整落盘的 JSONL 边界，不只导出界面当前显示的 50 条。
- **实况速度校准**：预运行显示理论估算；任务产生至少 3 次评论页请求后，自动按真实页填充率、页面耗时、成功率与当前有效并发校准。
- **任务结算**：完成、暂停、冷却、停止或失败后，统一展示本轮耗时、累计命中、页数和请求数。
- **结构化日志**：逐页记录请求开始、成功、耗时、读取条数、失败以及 `403/429` 风控/限流。
- **Windows 应用内更新**：启动时检查最新 Release，下载后校验 SHA-512；安装前先保存扫描检查点，新版可继续未完成任务。

## 快速开始

1. 安装并启动“乐评寻踪”，在顶部选择“网易云音乐”或“QQ 音乐”。
2. 网易云任务填写用户主页 `id=` 后的纯数字 UID。“喜欢歌曲”来源需要有效登录会话；客户端会验证喜欢歌单确实属于目标 UID，不会用当前登录账号静默代替。
3. QQ 任务可填写数字 QQ、QQ 音乐个人主页 URL 或 EncryptUin。指定单曲时输入歌名/歌手并选择候选歌曲；公开喜欢列表不可访问时会明确报错，不会尝试绕过隐私设置或要求 QQ Cookie。QQ 表单旁的“EncryptUin 解析实验”只接受单次输入；官方 URL 不会被直接打开或跟随重定向。裸 Token 或携带 Token 的已知官方 URL 只做本地处理；数字候选的 canonical EncryptUin 解析和后续正向验证都是独立、显式的联网操作。代理池或显式代理存在时请求 fail-closed；只有用户明确勾选“允许本机直连”才会直连，绝不静默回退。
4. 如需代理，在“多 IP 池”中勾选 Clash Verge 配置并执行“自动优选”。Clash Verge 客户端无需开启系统代理或 TUN；工具会读取配置并启动自己的 Mihomo 进程。
5. 选择任务模式并开始扫描。新命中会立即出现在“实时结果”，需要留档时可导出 PDF。

完成一个用户后可以直接改成另一个 UID 再查询。若代理池已就绪，用户资料预检会轮换起始出口，并在当前出口发生网络或 5xx 瞬态故障时最多自动换 3 个已验证出口；界面会显示最终使用的节点和第几个出口成功。代理池运行但复核失败时不会偷偷回退本机直连。公开资料请求不附带登录 Cookie，因此旧登录会话失效也不会单独导致 `user_detail` 查询失败；喜欢歌曲等需要身份的数据仍按登录状态处理。若上游明确返回 404，客户端会直接提示“UID 不存在或资料不可访问”，不会把它误写成英文网络错误，也不会无意义地轮询所有出口。

UID 是用户主页的数字 ID，不是昵称。例如：

```text
https://music.163.com/#/user/home?id=123456789
                                      └─ UID
```

### 扫描模式怎么选

| 模式 | 适用场景 | 调度方式 |
| --- | --- | --- |
| 用户来源 · 听歌排行 | 不知道具体歌曲，优先查用户常听内容 | 候选歌曲按页轮转；剩余歌曲不足时自动时间分片 |
| 用户来源 · 喜欢歌曲 | 听歌排行不可读或需要补充范围 | 只读取目标 UID 所属的喜欢歌单，按歌曲 ID 去重后轮转 |
| 用户来源 · 两者 | 希望扩大候选歌曲覆盖 | 听歌排行与目标 UID 喜欢歌单的去重并集，总数不等于单独的喜欢数 |
| 单曲并行 | 已知歌名，且评论区很大 | 搜索选曲 + 时间分片 + 多出口 + 页级重新入队 |
| QQ 单曲顺序 | 已知 QQ 歌名 | 搜索选曲；一首歌保持一条严格递减的 SeqNo 链，每页可公平换出口但不并发推进同一游标 |
| QQ 公开喜欢 | 目标公开了“我喜欢”歌曲 | 先分页发现歌曲，再用有界 Worker 跨歌曲扫描；同一歌曲仍只有一条 SeqNo 链 |

用户评论历史接口只适合查询当前登录账号本人。CLI 的 `--strategy auto` 只在登录 UID 与目标 UID 相同时转入该路径；查询其他用户时使用公开歌曲评论精确匹配。

普通启动（不勾选“新建状态”）每次都会刷新当前所选来源的歌曲目录，然后按歌曲 ID 与持久化断点对账：已完成的歌曲不再请求，未完成歌曲从原 cursor/分片继续，只有真正新增的歌曲从初始范围开始。排名、歌名或 `record`/`likes` 标签变化只更新元数据，不会重置评论进度；从上游移除的历史歌曲也不会被破坏性删除。如果目录刷新失败或 `both` 只有一个来源成功，客户端保留上次完整目录并显示来源错误，不会用不完整响应缩短断点。

用户来源模式使用 target-v3 的 UID 级完整覆盖账本。同一 UID 在 `record` / `likes` / `both` 之间遇到已自然扫描到末尾的歌曲时会直接复用；暂停中的歌曲、冷却/失败歌曲、达到每歌页数上限或不完整分片都不会进入账本。账本按 UID 隔离，并使用跨进程文件锁和原子合并避免多客户端丢失 songId。勾选“新建状态”/使用 `--fresh` 会明确绕过覆盖复用并重扫当前任务，但 target-v3 JSONL 仍按 `commentId` 去重。

### 导出结果的口径

PDF 从当前任务描述符对应的追加式 JSONL 文件读取全部已保存命中，不受界面只保留最近结果的限制。导出开始时会固定文件字节边界，因此任务可以继续运行，生成过程不会持续追赶新写入内容；导出瞬间尚未完整落盘的尾行留到下一次导出。报告请求只接受本机连接，并校验 `platform + mode + jobId + canonical target`；旧版 `uid` 查询只作为网易云兼容入口。读取过程中切换任务会拒绝导出，避免把两个任务混在一起。为防止超大 HTML/PDF 撑爆客户端，单份报告上限为 64 MiB JSONL 或 20,000 条命中，超过时会明确提示缩小任务范围，不会静默截断。报告只根据已验证的歌曲 ID/MID 重建对应平台的官方链接，不信任结果文件中保存的任意 URL。

target-v3 的用户来源结果按 UID 共享一个 canonical JSONL，因此 `record` / `likes` / `both` 复用已覆盖歌曲时，旧命中仍会出现在当前 UID 的实时结果和完整报告中。“新建状态”只重建当前来源检查点，不会清空 canonical 结果；新扫描重新发现文件中已有的评论时，会在当前检查点计数一次，但不会向 JSONL 重复追加。未在本次扫描重新出现的历史行只计入结果页/报告的文件累计结果，不冒充当前检查点命中。评论、昵称和歌曲名只作为文本输出，不会作为 HTML 执行；超长评论会无损拆成带“续”标记的打印行跨 A4 页面排版，避免 Chromium 在一个超长表格行跨页时发生文字重叠。

## 并发、后期降速与风控

### 在客户端设置总工作线程上限

进入左侧“搜索任务”页面，在窗口顶部任务栏的“拓扑”右侧可以看到两个数字输入框：

| 设置 | 可选值 | 作用 |
| --- | --- | --- |
| 总工作线程上限 | `1..32`，默认 `8` | 硬性限制整个任务实际创建的 Worker 总数；QQ 公开喜欢的任务级在途上限随实际 Worker 动态扩展，最高 32 |
| 任务出口上限 | `0..32`，默认 `0` | 限制本次任务最多使用多少个已验证出口；`0` 表示轮换使用全部已验证出口 |

请在启动任务前修改；任务运行或停止过程中输入框会锁定，避免中途改变调度拓扑。顶部“拓扑”会直接显示实际工作线程，例如“自动使用 8/8 出口 · 实际 8 工作线程 · 每出口≤3”。

自动模式会把全部已验证出口加入本次任务。实际 Worker 数固定为 `min(出口数 × 每出口工作线程, 总工作线程上限)`；例如 8 出口 × 每出口最多 3、总上限 8，实际只创建 8 个 Worker，不会先创建 24 个再排队。只有手动填写正数“任务出口上限”时才会缩小本次任务的出口集合。

每个代理出口是一个 Lane，同一 Lane 上的请求共享 `RequestGovernor`。固定数量的工作线程在每一页前都向共享 `LaneAllocator` 领取 permit：全部健康出口按全局游标公平轮转，单出口同时占用不超过“每出口工作线程”。某个出口失败或恢复中时，工作线程不退出，容量会转移给其他健康出口。

并行歌曲页分别显示“不同歌曲数”和“活跃 Worker / 配置 Worker”。歌曲行在一页结束后会保留为“等待调度 / 0 Worker”，直到 Worker 切换到别的歌曲或该歌曲完成；前端按歌曲 ID 复用现有表格行，不再整表重建。进度优先显示累计完成页数和处理中分片数；分片自己的“第 1 页”不再冒充整首歌的全局进度。

手动少用出口可以减少本地连接和调度对象，但默认会使用全部出口来分散单个公网 IP 的请求量和提高故障切换余量；总工作线程上限不变时，多出口不会绕过总上限。界面会明确显示“已用/可用出口、活跃/配置工作线程、总工作线程上限、每出口工作线程”，避免把歌曲数或代理池容量误认为当前请求并发。

网易云代理请求共享自适应主机级启动节奏：请求起始间隔默认在 80–120ms 间随机化，聚集故障会降低有效在途数并拉长节奏。QQ 音乐仍使用独立任务 Gate，但不再固定为 4：公开喜欢模式按实际 Worker 容量动态设为 1–32 在途，同步扩展有界检查点槽；聚合启动间隔从小拓扑的 250ms 逐步缩短，最低 80ms。每个 Lane 的 Governor 仍独立保持用户设置的“每出口请求间隔”，增加总 Worker 不会缩短同一 IP 的节奏。QQ 代理 HTTPS 还会复用已健康建立的 CONNECT/TLS 隧道，任务取消或代理失败时显式销毁；QQ 单曲由于 SeqNo 依赖仍始终只有一条请求链。

这些控制能减小突发尖峰和故障重试风暴，但不能隐藏高并发流量，也不能保证不触发上游策略。持续只拿最低延迟节点主要改善响应时间，并不会让请求模式不可见；工具因此同时要求出口网段分散、控制总并发和保留每出口节奏。

当代理连接在大响应传输中被提前关闭时，上游库可能报告 `Unexpected end of JSON input`。这属于响应截断或代理链路异常，不是明确的 `403/429` 风控。客户端会严格拒绝空正文、半截 JSON、缺失分页字段、无法识别作者的页内评论和不下降的游标，在同一游标上按瞬态 `502` 重试，绝不会把它当作“评论已经读完”。如果 10 秒内聚集 3 次传输故障，主机级传输门会自动将当前有效并发减半（最低 4），同时拉长请求启动间隔；稳定成功后再逐步恢复到用户设置的上限。运行界面会显示“自动降载至 N”，因此把总工作线程上限设为 18 代表允许的上限，不代表网络异常时仍强制维持 18。

“当前读取速度”统计成功页面实际返回的原始评论条数，并使用最近 10 秒滚动窗口显示为 `N 条/秒`；它不是命中速度，也不是按页大小推算的理论值。新任务会清零，连续 10 秒没有成功读取或任务结束后显示为 0。

“速度估算”不会再用代理池对 20 条评论所做的轻量探测冒充 1000 条页面的真实耗时，也不会简单用“评论总数 ÷ 每页条数”估算用户来源任务。用户来源按每首歌独立分页；单曲并行按实际物理时间分区分页。任务运行并积累至少 3 个页面样本后，界面会分别显示逻辑页面数和包含重试的远端尝试数；平均延迟只统计真正调用上游接口的时间，不把代理排队、启动间隔或重试退避重复算进网络耗时。校准还会使用当前分片内的有效页填充、远端尝试成功率、AIMD 有效并发与实际拉长后的启动间隔。只有目标和页大小、延迟、出口/线程、总工作线程上限、来源/分片等配置都与样本任务一致时才复用实况数据；运行前或配置改变后会明确回到理论模型。

早期版本会让 Worker 一直扫完一首歌或一个时间分片。评论密度不均时，后期只剩少数“大任务”，其他 Worker 会提前退出，看起来像请求被风控。当前版本采用**一页一个工作项 + 容量匹配的启动分片 + 运行中自适应拆分**：处理完一页后重新入队；新单曲任务只物化 `min(配置分片数, 实际 Worker, 当前传输容量)` 个初始分片，避免 8 个 Worker 为默认 96 个分片支付大量空尾页/边界请求，随后再按空闲 Worker 拆分剩余范围。配置分片数仍作为检查点兼容键，旧任务可继续续跑。因此只有一首候选歌时，也能让多个代理出口并行扫描互不重叠的时间范围。若启用了每歌页数上限，最后一个允许页自然返回结束会按完整覆盖结算；只有达到上限后仍有未读范围才标记为截断。

仍可能出现合理降速：

- 未完成页面已少于 Worker 数，任务正在自然收尾。
- 某些出口网络失败，未完成工作已转移给健康出口。
- 远端返回 `403/429`，对应出口进入冷却；用户来源在所有出口都受阻时会保存恢复时间。
- 实际网络延迟高于请求起始间隔。

打开“运行日志”可以直接区分这些情况。`page_success` 表示成功读取；`page_failure` 表示网络/业务失败；`rate_limited` 表示明确收到风控或限流信号；`adaptive_split` 表示调度器发现空闲线程并拆分剩余任务，它不是风控。

## 代理池

桌面界面可以自动发现 Clash Verge 的配置和 Mihomo 内核，默认从 48 个候选节点中优选并保留 8 个出口。代理池容量与单次任务出口数相互独立：任务可只使用其中一部分，且不会重建或缩小共享代理池。配置区提供全选/取消全选，也可逐项勾选；合并时会在不同配置之间公平轮转、去除重复节点并安全改名重名节点。也可切换到“其他代理池”，每行导入一个 HTTP/HTTPS 代理。

代理池状态灯由本地服务报告的池状态驱动并持续显示：灰色为未构建，黄色闪烁为构建/验证中，绿色“已就绪”表示本轮优选已经返回通过验证的出口，橙色为后台复测待重试，红色为构建失败。构建或后台复测期间，任务启动和代理池停止按钮都会锁定，避免在验证尚未完成时触发冲突操作；任务启动时服务端仍会再次校验出口。

多配置会生成一份临时配置和一个独立 Mihomo 进程，不会要求开启 Clash Verge 的系统代理或 TUN。当前只合并已物化的内联叶子节点；含 `proxy-providers` 或 `dialer-proxy` 链式依赖的配置会明确拒绝，避免静默丢节点或生成无效引用。

优选不只比较完整 IP，还会限制网络前缀：

- IPv4：同一 `/24` 只保留延迟最低的一个出口。
- IPv6：同一 `/48` 只保留延迟最低的一个出口。
- 每个入选出口都必须通过公网 IP 检查和网易云评论接口实测。

如果不同网段的可用出口不足，工具会取消构建，不会用同网段 IP 强行补齐。代理池在空闲时每约 60 秒重新验证出口和延迟；启动任务可复用 90 秒内且仍满足独立网段的验证结果，过期或异常节点仍会完整复核。扫描任务运行时暂停后台复测，避免额外请求绕过当前限速。

CLI 示例：

```powershell
# 从 Clash Verge 配置构建 8 个网络前缀互异的出口
npm run start -- proxy-pool start --size 8 --candidates 48

# 合并两套配置（--source-config 可重复）
npm run start -- proxy-pool start --source-config C:\path\a.yaml --source-config C:\path\b.yaml

# 查看或停止工具管理的代理池
npm run start -- proxy-pool status
npm run start -- proxy-pool stop
```

> [!NOTE]
> 代理池文件会使用与扫描检查点相同的原子写入和 Windows 文件锁重试机制保存在本地，并被 Git 忽略。含账号密码的代理 URL 不会通过 GUI API 原样返回。已托管 Mihomo 进程在停止前会校验命令行与配置路径，避免 PID 复用时误杀其他进程。

代理池的“已验证”表示出口 IP 和网易云探测已通过，不等于 QQ 域已预先验证。QQ 的每个实际请求仍独立 fail-closed：代理拒绝、超时或失效时只会换健康 Lane、暂停或报错，绝不会偷偷回退本机直连。

## 结算、日志与本地数据

每个 GUI 任务都有独立 UUID。开始时间从服务端接受任务起计算，结束后 `elapsedMs` 会冻结，后续轮询不会让耗时继续增长。结算画面按“检索模式 + 任务 UUID”只展示一次，覆盖 `complete`、`matched`、`paused`、`cooldown`、`dry-run`、`stopped` 和 `error`。

需要注意两个口径：

- **累计命中**：来自当前来源检查点；跨来源复用的旧命中仍在当前 UID 结果页/报告中可见，但不会冒充本检查点新命中。
- **本轮耗时**：只属于当前任务 UUID，不累加过往运行时间。

日志以 JSONL 存储，每行一个结构化事件。内容不记录 Cookie 或代理密码。桌面客户端将数据写入 Electron `userData` 目录；从源码运行 Web/CLI 时使用项目内的以下目录：

| 路径 | 内容 |
| --- | --- |
| `data/*.json` | 用户来源或单曲分片检查点 |
| `data/*.jsonl` | 命中评论，按 `commentId` 去重 |
| `data/web-song-coverage-<UID>-target-v3.json` | GUI 的 UID 级完整歌曲覆盖账本 |
| `data/logs/<mode>-<uuid>.jsonl` | 任务调试日志 |
| `data/qq/state-<task-key>.json` | QQ 独立 SeqNo 扫描状态 |
| `data/qq/comments-<task-key>.jsonl` | QQ 命中结果，按 `(songId, commentId)` 去重 |
| `data/logs/qq-<uuid>.jsonl` | QQ 任务结构化日志 |
| `data/resume-task.json` | 最近一次 GUI 任务的非敏感表单参数 |
| `.ncm/cookie.txt` | 二维码登录会话 |
| `.ncm/proxy-pool.json` | 当前代理池状态与验证结果 |

这些路径都不应提交到 Git。

### 更新时如何保留扫描进度

Windows 客户端下载完更新后，如果扫描仍在运行，“重启并安装”会变为“保存进度并重启”。客户端通过全局任务协调器停止真实活跃的网易云或 QQ 任务，等待状态离开运行/停止中并完成强制检查点，再交给安装器重启；45 秒内无法确认时会取消安装，避免带着不确定状态退出。任务仍在启动或 QQ 歌曲查询尚未结束时也不会直接安装。
如果此时正在构建或复测代理池，更新会保持全局屏障并提示等待，不会绕过代理池租约强制终止 Mihomo；取消安装后屏障会释放。

任务参数和扫描状态都保存在 Electron 的同一个 `userData` 目录，不随应用版本替换。新版启动后会回填上次平台、模式、目标、歌曲 ID 与并行参数，但不会自动开始；保持“新建状态”关闭并再次开始，即可从相同检查点继续。旧 QQ 恢复参数若保存了大于 25 的评论页大小，会在任何远端请求前归一为 25，并显示 `qq-comment-page-size-25` 调整提示。极端退出情况下可能重复少量尚未确认的在途页面，结果 writer 会按各平台的稳定键去重。

target-v3 是一次显式安全边界升级：GUI 的听歌排行、喜欢歌曲和两者都使用 `web-state-<UID>-<source>-target-v3.json`，并共享受 owner 隔离的 `web-comments-<UID>-target-v3.jsonl` 与 `web-song-coverage-<UID>-target-v3.json`。新版不会静默导入 target-v2 的 likes/both 文件，也不会把可能混入旧来源的未版本化 record 共享文件当作可信覆盖。旧文件保留在本地供手工归档，不会被删除或自动改写。CLI 默认路径同样带 target-v3 后缀，也可通过 `--state` / `--output` / `--coverage` 显式选择路径。

## 分页与检查点语义

- 歌曲评论使用 `comment_new` 降序时间游标，默认每页 1000 条，可配置范围为 `1..2000`。
- `hasMore=true` 时，下一游标必须严格向过去推进。空页但游标有效时会继续；游标缺失或不前进时保留可续跑状态，不会误报完成。
- 修改每页条数后不能直接恢复旧游标；请勾选“新建状态”或使用 `--fresh`。
- 用户来源检查点当前为 version 3，会持久化每首歌的未完成时间分片和最近一次目录对账统计；底层加载器仍能读取 version 1/2 的显式指定断点，但 GUI/CLI 的 target-v3 默认路径不会自动探测旧文件。GUI 代理池并行或 CLI 串行入口都能按 songId 保留分片状态。
- 从旧 `comment_music` offset 检查点迁移时，已完成歌曲保留，未完成歌曲从任务创建时间重扫，JSONL 继续去重。
- QQ 评论页使用严格递减的十进制 SeqNo，范围 `1..25`、默认 25；公开喜欢来源页是独立接口，范围 `1..500`、默认 500。
- QQ 结果必须先完成 `write + fsync`，随后再次检查取消状态，最后才提交 seen key、页码和 cursor；停止、持久化失败或截断都不能误报完整覆盖。

## 代码结构

| 模块 | 职责 |
| --- | --- |
| `src/api.ts` | 网易云请求适配、响应归一化和加解密底座 |
| `src/scanner.ts` | 听歌排行/喜欢列表收集、多 Lane 页级调度和断点恢复 |
| `src/parallel-scanner.ts` | 单曲时间分片、自适应尾部拆分、页级队列和出口故障转移 |
| `src/qq-music/` | QQ Client、SeqNo Scanner、状态/结果 writer、代理 fetch、TransportGate 与 benchmark 模型 |
| `src/qq-job-manager.ts` | QQ Dashboard 应用层、generation、路径、代理 Lane、日志、结算与报告快照 |
| `src/qq-cli.ts` | 独立 QQ 命令行入口，不复制 Dashboard manager |
| `src/time-shards.ts` | 两种扫描器共用的半开时间分片创建与拆分规则 |
| `src/worker-topology.ts` | 计算受主机硬上限约束的实际 Worker 数 |
| `src/lane-allocator.ts` | 在全部健康出口间公平分配 permit，并守住每出口并发上限 |
| `src/song-metadata.ts` | 对喜欢列表和旧检查点中缺失的歌曲名称做有界批量补全 |
| `src/proxy-lane-selection.ts` | 自动模式保留全部已验证出口，或按手动上限裁剪出口集合 |
| `src/clash-profile-merge.ts` | Clash 配置校验、多配置公平候选、节点去重和重名处理 |
| `src/work-queue.ts` | 可等待重新入队的异步工作队列，避免 Worker 过早退出 |
| `src/cursor-pagination.ts` | 两种扫描器共用的降序游标推进规则 |
| `src/checkpoint-coordinator.ts` | 多 Lane 扫描共用的实时状态节流、不可变快照和串行检查点写入 |
| `src/task-coordinator.ts` | 全局单任务租约、代理池互斥与耗时计算 |
| `src/task-log.ts` | 按任务 UUID 串行写入结构化调试日志 |
| `src/result-accumulator.ts` | 统一 JSONL 去重后的检查点命中 ID 与计数更新 |
| `src/page-performance.ts` | 汇总真实评论页耗时、页填充与最终成功率，供运行中速度估算校准 |
| `src/jsonl-snapshot.ts` | 按导出开始时的固定字节边界读取完整追加式结果文件 |
| `src/result-report.ts` | 生成安全、可打印、支持中文和长评论跨页的 A4 结果报告 |
| `src/mihomo-pool.ts` | Clash Verge 发现、Mihomo 生命周期、网段去重与连通验证 |
| `src/server.ts` | 本地 API、任务/登录/代理池编排和结算快照 |
| `src/electron-main.ts` | 桌面窗口、内置服务生命周期、运行目录隔离与沙箱 PDF 打印 |
| `src/windows-updater.ts` | Windows 更新检查、下载、校验和重启安装状态机 |
| `web/` | 本地操作界面、实时结果、日志和结算画面 |

项目不使用数据库。评论结果是追加写入的 JSONL，扫描状态是 JSON，实时 UI 失败不得中断结果持久化。客户端启动扫描时会流式读取历史 JSONL 并定期让出事件循环，避免大结果文件造成窗口卡顿。实时结果按搜索发现顺序展示（最新发现优先），不会再按评论发布时间重排。喜欢来源通过目标 UID 所属的 `specialType=5` 歌单详情读取 `trackIds`，而不是直接使用可能被登录态覆盖身份的 `likelist`；只返回 ID 时会在后端批量补全歌曲名称并写入检查点。底层依赖固定为 `@neteasecloudmusicapienhanced/api@4.39.0`，避免上游变更直接影响正在续跑的任务。
