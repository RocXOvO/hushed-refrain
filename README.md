乐评寻踪支持网易云音乐和 QQ 音乐。网易云任务按数字 UID 精确匹配公开评论，可从听歌排行、喜欢歌曲、目标用户自建公开歌单或其组合发现歌曲，也可对单曲做时间分片；QQ 任务将数字 QQ、个人主页 URL 或 EncryptUin 解析为规范目标，按完整 EncryptUin 精确匹配，可扫描指定单曲或公开“我喜欢”歌曲。桌面客户端、本地 Web 控制台和 CLI 共用断点续跑、多出口、实时结果与结构化日志能力。

> [!IMPORTANT]
> 请只在合法、合理的场景中查询公开数据，尊重用户隐私、平台规则与请求频率。该工具不能绕过私密的听歌排行、喜欢列表或普通用户歌单，也不保证找到用户的全部历史评论。

> [!WARNING]
> 当前 Web 控制台按本机可信使用设计。请保持默认 `127.0.0.1`，不要把 `npm run web` / `web --host` 绑定到 `0.0.0.0`、局域网或公网。当前扫描任务互斥只覆盖单个进程；同一数据目录不要同时运行两个桌面客户端、CLI 或 Web 服务扫描同一目标，否则确定性的检查点和 JSONL 可能发生竞争。详见 [全局代码审计](docs/code-audit.md)。

## 功能一览

- **顶部双平台工作区、内部四视图**：顶部在网易云与 QQ 音乐工作区之间切换；网易云“用户来源 / 单曲并行”与 QQ 音乐“单曲顺序 / 公开喜欢”相互隔离，不会串任务、结果或日志。
- **统一紧凑导航与可缩放布局**：网易云和 QQ 音乐共用相同的紧凑图标导航；窗口横向或纵向缩放时，工具栏和浮动面板会重排或互斥，长表格与面板内容在各自区域滚动，不会因平台切换挤占主工作区。
- **歌名搜索**：单曲任务可输入歌名或歌手并从候选列表选择，不需要先去官网查找歌曲 ID；纯数字 ID 仍作为高级兼容入口。这些低频候选/元数据查询始终使用本机直连，不读取高并发扫描才需要的代理池；同关键词请求会单飞并短时缓存。
- **QQ 目标与 EncryptUin 实验**：QQ 两种任务都可在启动前点击用户探测，通过本机直连读取公开昵称，数字 QQ 头像使用腾讯公开 `qlogo.cn` 地址；这些普通查询不启动或读取代理池。任何直接纯数字输入（包括 19 位）或可逆 8/12/16 字符经典 EncryptUin 都显示完整 QQ 号；只有可逆 28 字符微信登录 Token 显示“微信用户”，不会暴露其内部 ID，也不会误称微信号或 QQ 号；无法反解但可用于扫描的 opaque 值显示完整 EncryptUin。官方链接只提取其中的身份，不回显整条 URL。扫描仍只按 canonical EncryptUin 匹配；默认 PDF 文件名作为用户明确可见的导出信息会显示完整目标，日志、错误和诊断继续脱敏。单次解析不提供批量导入、枚举或反查，复制完整 QQ 仍需明确点击。
- **双平台视觉**：网易云保留舒适的暖灰/红，QQ 改为中性黑灰/白灰底，仅用官方品牌绿 `#31c27c` 标识平台和关键状态，正文强调改用更深绿色，不再大面积铺青蓝。平台切换统一采用一次性的 Obsidian Silk Aperture：五道确定性绢缎褶皱把源平台色收拢到中性黑曜色，再以石墨绿、品牌绿和柔和薄荷揭开 QQ；结束时先把遮罩与忙状态交还给目标页面，下一合成帧再释放 GPU，避免末帧闪屏。导航不再显示无状态来源的装饰绿点，顶部真实服务徽章和代理池状态灯保留。没有平台切换动画模式按钮，也不会拆分、截图或移动真实业务页面。按钮共用短促一致的触感反馈与层级化圆角，禁用状态不再误显示 hover/按压效果；减少动效、隐藏页面或 WebGL 不可用时会立即完成切换。
- **主工作区 MeshLine Follow**：只响应精细鼠标在中央主工作区内的移动。四条独立绢线使用不同的弹簧、摩擦和环形偏移逐级跟随指针，宽度随移动速度平滑变化，两端自然收尖；其动力学参考 MIT 许可的 Makio MeshLine Follow 演示，客户端用轻量 WebGL2 三角带渲染而不引入整套 Three.js/Vue 运行时。最后一次移动 420 ms 后清空并不再占用动画帧。可在“全局设置”关闭；桌面客户端会持久保存，浏览器模式只对当前会话生效且刷新后恢复默认开启。减少动效、粗指针、页面失焦/隐藏、弹窗或平台切换期间自动停用。
- **断点续跑**：歌曲游标、分片进度和请求数会原子化写入 JSON 检查点；用户来源与 QQ 任务在全部出口冷却时还会保存恢复时间。单曲并行会保留未完成分片，但当前不承诺跨重启保存统一的冷却截止时间。Windows 文件短暂占用会自动重试，并可从已完整写入的遗留临时文件恢复。
- **自适应页级调度**：Worker 每次只处理一页；用户来源只剩一首歌时也会把未读时间范围拆给多个出口，减少扫描后期的并发长尾。
- **独立出口代理池**：可勾选一套或多套 Clash Verge 配置合并优选，或导入其他 HTTP/HTTPS 代理；右侧 Inspector 收起时，构建或后台复测会显示可点击的全局进度提示。
- **明确启动与全局停止**：提交任务时，右下角状态点展开为只含当前启动阶段和细进度条的胶囊，不显示虚假的耗时；顶部停止按钮始终停止真实活跃的平台任务，并等待任务 Lease 释放和强制检查点完成。
- **实时可观测**：中央“并行歌曲”页面展示正在扫描的歌曲、活跃/配置 Worker，以及每首歌已读评论数和进度条；主区持续显示总进度、累计请求、命中、实时评论与最近 10 秒实际评论读取速度。Live Task 与 QQ 昵称/头像补全都走独立低频本机直连，不占用扫描代理 Lane；QQ 补全在 scanner 启动后异步执行，“微信用户”不请求资料并固定使用该称谓和默认头像。
- **完整结果 PDF**：实时结果可随时导出为 A4 报告；Windows 从打开保存对话框起持续累计耗时，选定路径后显示“读取结果 / 准备排版 / 生成 / 写入”和取消按钮，各阶段有界超时，取消、失败和成功都有明确反馈，不会无限停在“正在生成”。
- **实况速度校准**：预运行显示理论估算；任务产生至少 3 次评论页请求后，自动按真实页填充率、页面耗时、成功率与当前有效并发校准。
- **任务结算**：完成、暂停、冷却、停止或失败后，统一展示本轮耗时、累计命中、页数和请求数。
- **结构化日志**：逐页记录请求开始、成功、耗时、读取条数、失败以及 `403/429` 风控/限流。
- **Windows 应用内更新**：启动时检查最新 Release，下载后校验 SHA-512；安装前先保存扫描检查点，新版可继续未完成任务。

## 快速开始

1. 安装并启动“乐评寻踪”，在顶部选择“网易云音乐”或“QQ 音乐”。
2. 网易云任务填写用户主页 `id=` 后的纯数字 UID，并选择听歌排行、喜欢歌曲、用户歌单、排行 + 喜欢或全部来源；排行范围可选全部时间、最近一周或两者。“喜欢歌曲”来源需要有效登录会话。喜欢歌单和普通歌单都只接受显式属于目标 UID 的创建者证据，不会把订阅歌单、缺失创建者或当前登录账号静默映射为目标 UID；目录以详情返回的显式、有效且不重复的歌曲 ID 为准，真实截断、重复、非法 ID 或所有者不一致会拒绝写入不完整目录。
3. QQ 任务可填写数字 QQ、QQ 音乐个人主页 URL 或 EncryptUin。指定单曲时输入歌名/歌手并选择候选歌曲；公开喜欢列表不可访问时会明确报错，不会尝试绕过隐私设置或要求 QQ Cookie。QQ 工作区不复用网易云 Cookie，右上角固定显示“本地服务”并隐藏网易云二维码登录按钮。QQ 表单旁的“EncryptUin 解析实验”只接受单次输入；官方 URL 不会被直接打开或跟随重定向。裸 Token 或携带 Token 的已知官方 URL 只做本地处理；实验数字候选、正式启动时的数字 canonical 解析、正向验证和 scanner 启动后的昵称/头像补全，均使用独立、4 秒有界的本机直连辅助 Lane，不读取代理池或表单手动代理。正式评论/来源分页才使用用户选择的代理池并保持 fail-closed；“允许本机直连”只控制正式扫描。
4. 如需代理，在“多 IP 池”中勾选 Clash Verge 配置并执行“自动优选”。Clash Verge 客户端无需开启系统代理或 TUN；工具会读取配置并启动自己的 Mihomo 进程。
5. 选择任务模式并开始扫描。新命中会立即出现在“实时结果”，需要留档时可导出 PDF。

完成一个用户后可以直接改成另一个 UID 再查询。Dashboard 用户预探测、歌曲名搜索、数字歌曲详情以及任务期间的展示资料补全都是本机直连辅助查询，不读取高并发代理池；QQ 普通查询采用 4 秒有界超时。网易云用户预探测会以 100ms 间隔并行发起公开资料、听歌排行、喜欢歌曲和用户歌单读取（单请求 2 秒上限）；喜欢与普通歌单复用同一份首屏列表，同一 UID 在前端 60 秒内复用结果。列表仍有后页时，歌单数和歌曲数以 `+` 标明只是下限。目标自己的“喜欢的音乐”歌单明确不可见时显示“已开启隐私”；风控冷却单独显示，其他无法下结论的预检失败显示“暂时无法确认”，不会被误报为已确认的隐私状态；客户端不会尝试绕过隐私设置。NetEase Live Task `/api/user/profile` 仍用 `mode + jobId` 在请求前后校验活动任务和 UID/generation，但资料请求本身固定直连，不复用扫描 Lane/Governor/Gate。公开资料请求不附带登录 Cookie，因此旧登录会话失效也不会单独导致 `user_detail` 查询失败。若上游明确返回 404，客户端会直接提示“UID 不存在或资料不可访问”，不会把它误写成英文网络错误。

UID 是用户主页的数字 ID，不是昵称。例如：

```text
https://music.163.com/#/user/home?id=123456789
                                      └─ UID
```

### 扫描模式怎么选

| 模式 | 适用场景 | 调度方式 |
| --- | --- | --- |
| 用户来源 · 听歌排行 | 不知道具体歌曲，优先查用户常听内容 | 候选歌曲按页轮转；剩余歌曲不足时自动时间分片 |
| 用户来源 · 喜欢歌曲 | 听歌排行不可读或需要补充范围 | 只读取目标 UID 所属的喜欢歌单，按歌曲 ID 去重后轮转 |
| 用户来源 · 用户歌单 | 需要扫描目标用户创建的其他公开歌单 | 排除“喜欢的音乐”和订阅歌单，严格验证创建者与详情后合并歌曲 |
| 用户来源 · 排行 + 喜欢 | 希望扩大常听与喜欢覆盖 | 听歌排行与目标 UID 喜欢歌单的去重并集 |
| 用户来源 · 全部来源 | 希望覆盖所有当前支持的公开目录 | 排行、喜欢和自建公开歌单按歌曲 ID 去重；同一歌曲保留全部来源标签 |
| 单曲并行 | 已知歌名，且评论区很大 | 搜索选曲 + 时间分片 + 多出口 + 页级重新入队 |
| QQ 单曲顺序 | 已知 QQ 歌名 | 搜索选曲；一首歌保持一条 SeqNo 游标链，每页可公平换出口但不并发推进同一游标 |
| QQ 公开喜欢 | 目标公开了“我喜欢”歌曲 | 先分页发现歌曲；顶部“总工作线程上限”直接控制跨歌曲 Worker 总数，单出口也不会自动缩成 1；同一歌曲仍只有一条 SeqNo 链 |

用户评论历史接口只适合查询当前登录账号本人。CLI 的 `--strategy auto` 只在登录 UID 与目标 UID 相同时转入该路径；查询其他用户时使用公开歌曲评论精确匹配。

普通启动（不勾选“新建状态”）每次都会刷新当前所选来源的歌曲目录，然后按歌曲 ID 与持久化断点对账：已完成的歌曲不再请求，未完成歌曲从原 cursor/分片继续，只有真正新增的歌曲从初始范围开始。`recordScope=both` 会分别读取全部时间和最近一周；所有成功目录按歌曲 ID 合并，同一歌曲只扫描一次，但 `memberships` 会保留 `record`、`record-week`、`likes` 或 `playlists` 各自的排名/播放/评分证据。旧状态没有 `memberships` 时会从原来源字段补全。排名、歌名或来源标签变化只更新元数据，不会重置评论进度；从上游移除的历史歌曲也不会被破坏性删除。组合来源中的单个范围或歌单详情失败时会保留其他成功目录和来源错误；整个独立来源都失败时不会把不完整响应写成完整目录。进度中“目录未读取 · 数量未知”表示尚未成功读到来源；只有已读取目录后显示 0，才代表确认为空。

用户来源模式使用 target-v3 的 UID 级完整覆盖账本。同一 UID 的 `record`、`likes`、`playlists`、`both` 与 `all` 在遇到已自然扫描到末尾的歌曲时会直接复用；暂停中的歌曲、冷却/失败歌曲、达到每歌页数上限或不完整分片都不会进入账本。账本按 UID 隔离，并使用跨进程文件锁和原子合并避免多客户端丢失 songId。勾选“新建状态”/使用 `--fresh` 会明确绕过覆盖复用并重扫当前任务，但 target-v3 JSONL 仍按 `commentId` 去重。

### 导出结果的口径

PDF 从当前任务描述符对应的追加式 JSONL 文件读取全部已保存命中，不受界面只保留最近结果的限制。导出开始时会固定文件字节边界，因此任务可以继续运行，生成过程不会持续追赶新写入内容；导出瞬间尚未完整落盘的尾行留到下一次导出。报告请求只接受本机连接，并校验 `platform + mode + jobId + canonical target`；旧版 `uid` 查询只作为网易云兼容入口。读取过程中切换任务会拒绝导出，避免把两个任务混在一起。为防止超大 HTML/PDF 撑爆客户端，单份报告上限为 64 MiB JSONL 或 20,000 条命中，超过时会明确提示缩小任务范围，不会静默截断。报告只根据已验证的歌曲 ID/MID 重建对应平台的官方链接，不信任结果文件中保存的任意 URL。

Windows 保存对话框由用户自行决定等待时间；默认 PDF 文件名会直接显示当前任务的完整 UID/EncryptUin，再把 Windows 禁止字符和控制字符替换为兼容字符，同时清理尾部点号/空格、避开设备保留名、把主文件名限制为最多 180 个字符，并固定使用 `.pdf` 扩展名。进度中的 `elapsedMs` 从导出开始累计并包含保存对话框等待，选定路径后再显示读取报告、等待字体、生成 PDF 与原子写入阶段。该值是单调累计耗时，不是单独阶段耗时；相邻阶段差值才可用于定位阶段成本。选定路径后的四阶段分别有30/15/180/30秒上限，共用一个取消信号；成功、取消、超时、隐藏报告进程异常或普通失败都会关闭隐藏窗口、移除监听并释放单飞锁，可立即重试。写入超时会取消尚未提交的原子写；若系统 rename 已经进入内核，则同一保存路径的跨进程锁会保留到它结算，同路径重试排在其后并成为最终文件。取消会提示“已取消 PDF 导出”；失败只显示稳定阶段原因，并把不含 UID、EncryptUin、评论正文、凭据或完整保存路径的诊断写到 `%APPDATA%\ncm-comment-finder\logs\desktop.log`。

target-v3 的用户来源结果按 UID 共享一个 canonical JSONL，因此任何来源组合复用已覆盖歌曲时，旧命中仍会出现在当前 UID 的实时结果和完整报告中。“新建状态”只重建当前来源检查点，不会清空 canonical 结果；新扫描重新发现文件中已有的评论时，会在当前检查点计数一次，但不会向 JSONL 重复追加。未在本次扫描重新出现的历史行只计入结果页/报告的文件累计结果，不冒充当前检查点命中。评论、昵称和歌曲名只作为文本输出，不会作为 HTML 执行；超长评论会无损拆成带“续”标记的打印行跨 A4 页面排版，避免 Chromium 在一个超长表格行跨页时发生文字重叠。

## 并发、后期降速与风控

### 在客户端设置总工作线程上限

进入左侧“搜索任务”页面，在窗口顶部任务栏的“拓扑”右侧可以看到两个数字输入框：

| 设置 | 可选值 | 作用 |
| --- | --- | --- |
| 总工作线程上限 | `1..32`，默认 `8` | 硬性限制整个任务实际创建的 Worker 总数；QQ 公开喜欢的任务级在途上限随实际 Worker 动态扩展，最高 32 |
| 任务出口上限 | `0..32`，默认 `0` | 限制本次任务最多使用多少个已验证出口；`0` 表示轮换使用全部已验证出口 |

请在启动任务前修改；任务运行或停止过程中输入框会锁定，避免中途改变调度拓扑。顶部“拓扑”会直接显示实际工作线程。QQ 公开喜欢的唯一 GUI Worker 容量就是这个主机上限；选择出口后，后端自动把许可按 `ceil(主机上限 / 实际出口数)` 分配到各出口，所以单出口配合主机上限 8 会调度 8 个跨歌曲 Worker，而不是 1 个。QQ 单曲仍受 SeqNo 游标依赖约束，实际只有一条 Worker/请求链，界面会同时显示这一协议限制和保存的主机上限。

自动模式会把全部已验证出口加入本次任务。网易云实际 Worker 数固定为 `min(出口数 × 每出口工作线程, 总工作线程上限)`；例如 8 出口 × 每出口最多 3、总上限 8，实际只创建 8 个 Worker，不会先创建 24 个再排队。QQ 公开喜欢不再提供第二个“每出口 Worker”容量输入，而是始终以主机上限为 Worker 总数并自动派生每出口许可。只有手动填写正数“任务出口上限”时才会缩小本次任务的出口集合。

每个代理出口是一个 Lane，同一 Lane 上的请求共享 `RequestGovernor`。固定数量的工作线程在每一页前都向共享 `LaneAllocator` 领取 permit：全部健康出口按全局游标公平轮转。网易云单出口占用不超过用户设置的“每出口工作线程”；QQ 公开喜欢不超过后端自动派生的每出口许可。某个出口失败或恢复中时，工作线程不退出，容量会转移给其他健康出口。

并行歌曲页分别显示“不同歌曲数”和“活跃 Worker / 配置 Worker”。歌曲行在一页结束后会保留为“等待调度 / 0 Worker”，直到 Worker 切换到别的歌曲或该歌曲完成；前端按歌曲 ID 复用现有表格行，不再整表重建。进度优先显示累计完成页数和处理中分片数；分片自己的“第 1 页”不再冒充整首歌的全局进度。

手动少用出口可以减少本地连接和调度对象，但默认会使用全部出口来分散单个公网 IP 的请求量和提高故障切换余量；总工作线程上限不变时，多出口不会绕过总上限。网易云界面显示用户配置的每出口线程；QQ 公开喜欢显示主机上限、可调度 Worker 和自动派生的每出口许可，避免把歌曲数或代理池容量误认为当前请求并发。

网易云与 QQ 音乐现在使用同一参数语义：`minDelayMs` 是同一出口相邻两次远程请求**开始时间**之间的真实最小间隔，随机抖动只会增加它，Worker 数不会再偷偷相除。Worker 只让慢网络等待互相重叠；实际页速率由“出口节奏、任务聚合 Gate、网络耗时/在途容量”三者中的最慢瓶颈决定。新 QQ 任务默认每出口 `300–399ms`，网易云单曲并行新默认 `111–144ms`；两平台任务聚合 Gate 健康时均为 `50ms`、无额外抖动，即最多约 20 次新请求启动/秒。故障时网易云 AIMD 仍会降低有效在途并拉长聚合节奏。QQ likes 的总在途上限随 Worker 容量在 `1..32` 内变化，QQ song 始终只有一条 SeqNo 链；50ms Gate 不会把同一歌曲变成并行游标。

旧任务不会被新默认覆盖。旧 QQ 保存的自定义 `3000/1000` 会原值恢复；无语义标记的旧网易云描述符会一次性等价换算到真实启动间隔（例如 `333/100`、3 Worker 变成 `111/34`），显示迁移提示并写入 `requestIntervalSemantics:"per-start-v1"`。换算只改表单节奏，不改变 `fresh`、歌曲进度、分片或 cursor，也不会重复换算。

理论量级示例：QQ likes 8 个健康出口、每出口 `300–399ms`、聚合 `50ms`、满 25 条/页时，聚合 Gate 约为 20 页/秒，即最多约 500 条/秒；4 出口时出口节奏约 11.4 页/秒，即约 286 条/秒。实际值还要乘页面填充率与成功率，并受网络耗时影响。20 页/秒下，平均网络耗时 400/800/1200ms 时约需 8/16/24 个在途请求填满流水线，这就是总 Worker 在慢网络下仍有价值的原因。

这些控制能减小突发尖峰和故障重试风暴，但不能隐藏高并发流量，也不能保证不触发上游策略。持续只拿最低延迟节点主要改善响应时间，并不会让请求模式不可见；工具因此同时要求出口网段分散、控制总并发和保留每出口节奏。

当代理连接在大响应传输中被提前关闭时，上游库可能报告 `Unexpected end of JSON input`。这属于响应截断或代理链路异常，不是明确的 `403/429` 风控。网易云客户端会严格拒绝空正文、半截 JSON、缺失分页字段、无法识别作者的页内评论和不能安全推进的时间游标，在同一游标上按瞬态 `502` 重试，绝不会把它当作“评论已经读完”。QQ 的 SeqNo 契约不同：同一页允许相等或局部乱序，仍以响应原始末条 SeqNo 作为下一游标；恢复页的每条 SeqNo 都必须严格小于请求 cursor，否则只隔离当前歌曲并保持其 cursor/pageNo 不动。如果 10 秒内聚集 3 次传输故障，主机级传输门会自动将当前有效并发减半（最低 4），同时拉长请求启动间隔；稳定成功后再逐步恢复到用户设置的上限。运行界面会显示“自动降载至 N”，因此把总工作线程上限设为 18 代表允许的上限，不代表网络异常时仍强制维持 18。

“当前读取速度”统计成功页面实际返回的原始评论条数，并使用最近 10 秒滚动窗口显示为 `N 条/秒`；它不是命中速度，也不是按页大小推算的理论值。新任务会清零，连续 10 秒没有成功读取或任务结束后显示为 0。

“速度估算”不会再用代理池对 20 条评论所做的轻量探测冒充 1000 条页面的真实耗时，也不会简单用“评论总数 ÷ 每页条数”估算用户来源任务。用户来源按每首歌独立分页；单曲并行按实际物理时间分区分页。任务运行并积累至少 3 个页面样本后，界面会分别显示逻辑页面数和包含重试的远端尝试数；平均延迟只统计真正调用上游接口的时间，不把代理排队、启动间隔或重试退避重复算进网络耗时。校准还会使用当前分片内的有效页填充、远端尝试成功率、AIMD 有效并发与实际拉长后的启动间隔。只有目标和页大小、延迟、出口/线程、总工作线程上限、来源/分片等配置都与样本任务一致时才复用实况数据；运行前或配置改变后会明确回到理论模型。

早期版本会让 Worker 一直扫完一首歌或一个时间分片。评论密度不均时，后期只剩少数“大任务”，其他 Worker 会提前退出，看起来像请求被风控。当前版本采用**一页一个工作项 + 容量匹配的启动分片 + 运行中自适应拆分**：处理完一页后重新入队；新单曲任务只物化 `min(配置分片数, 实际 Worker, 当前传输容量)` 个初始分片，避免 8 个 Worker 为默认 96 个分片支付大量空尾页/边界请求，随后再按空闲 Worker 拆分剩余范围。配置分片数仍作为检查点兼容键，旧任务可继续续跑。因此只有一首候选歌时，也能让多个代理出口并行扫描互不重叠的时间范围。若启用了每歌页数上限，最后一个允许页自然返回结束会按完整覆盖结算；只有达到上限后仍有未读范围才标记为截断。

仍可能出现合理降速：

- 未完成页面已少于 Worker 数，任务正在自然收尾。
- 某些出口网络失败，未完成工作已转移给健康出口。
- 远端返回 `403/429`，对应出口进入冷却；用户来源在所有出口都受阻时会保存恢复时间。
- 实际网络延迟高于请求起始间隔。

打开“运行日志”可以直接区分这些情况。`page_success` 表示成功读取；`page_failure` 表示网络/业务失败；`rate_limited` 表示明确收到风控或限流信号；`adaptive_split` 表示调度器发现空闲线程并拆分剩余任务，它不是风控。

## 代理池

桌面界面可以自动发现 Clash Verge 的配置和 Mihomo 内核，默认从 48 个候选节点中优选并保留 8 个出口。代理池容量与单次任务出口数相互独立：任务可只使用其中一部分，且不会重建或缩小共享代理池。配置区提供全选/取消全选，也可逐项勾选；合并时会在不同配置之间公平轮转、去除重复节点并安全改名重名节点。也可切换到“其他代理池”，每行导入一个 HTTP/HTTPS 代理。

代理池状态灯由本地服务报告的池状态驱动并持续显示：灰色为未构建，黄色闪烁为构建/验证中，绿色“已就绪”表示本轮优选已经返回通过验证的出口，橙色为后台复测待重试，红色为构建失败。构建或后台复测期间，任务启动和代理池停止按钮都会锁定，避免在验证尚未完成时触发冲突操作；任务启动时服务端仍会再次校验出口。

右侧 Inspector 收起时，构建和后台复测会在主界面显示一个可点击的全局提示；点击会展开 Inspector 并切到代理池详情。Inspector 已展开时不重复显示，状态轮询也不会反复改写相同提示或重播入场动画。

多配置会生成一份临时配置和一个独立 Mihomo 进程，不会要求开启 Clash Verge 的系统代理或 TUN。当前只合并已物化的内联叶子节点；含 `proxy-providers` 或 `dialer-proxy` 链式依赖的配置会明确拒绝，避免静默丢节点或生成无效引用。

优选不只比较完整 IP，还会限制网络前缀：

- IPv4：同一 `/24` 只保留延迟最低的一个出口。
- IPv6：同一 `/48` 只保留延迟最低的一个出口。
- 每个入选出口都必须通过公网 IP 检查和网易云评论接口实测。

如果不同网段的可用出口不足，工具会取消构建，不会用同网段 IP 强行补齐。代理池在空闲时每约 60 秒重新验证出口和延迟；启动任务可复用 90 秒内且仍满足独立网段的验证结果，过期或异常节点仍会完整复核。扫描任务运行时暂停后台复测，避免额外请求绕过当前限速。

CLI 示例：

```powershell
# 从 Clash Verge 配置构建 8 个网络前缀互异的出口
npm run start -- proxy-pool start --size 8 --candidates 48

# 合并两套配置（--source-config 可重复）
npm run start -- proxy-pool start --source-config C:\path\a.yaml --source-config C:\path\b.yaml

# 查看或停止工具管理的代理池
npm run start -- proxy-pool status
npm run start -- proxy-pool stop
```

> [!NOTE]
> 代理池文件会使用与扫描检查点相同的原子写入和 Windows 文件锁重试机制保存在本地，并被 Git 忽略。含账号密码的代理 URL 不会通过 GUI API 原样返回。已托管 Mihomo 进程在停止前会校验命令行与配置路径，避免 PID 复用时误杀其他进程。

代理池的“已验证”表示出口 IP 和网易云探测已通过，不等于 QQ 域已预先验证。QQ 正式评论/来源分页的每个代理请求仍独立 fail-closed：代理拒绝、超时或失效时只会换健康 Lane、暂停或报错，绝不会偷偷回退本机直连；用户/歌曲查询、数字 canonical 解析、EncryptUin 实验、Live Task 与资料补全都属于前述固定直连辅助通道。

## 结算、日志与本地数据

每个 GUI 任务都有独立 UUID。开始时间从服务端接受任务起计算，结束后 `elapsedMs` 会冻结，后续轮询不会让耗时继续增长。结算画面按“检索模式 + 任务 UUID”只展示一次，覆盖 `complete`、`matched`、`paused`、`cooldown`、`dry-run`、`stopped` 和 `error`。

需要注意两个口径：

- **累计命中**：来自当前来源检查点；跨来源复用的旧命中仍在当前 UID 结果页/报告中可见，但不会冒充本检查点新命中。
- **本轮耗时**：只属于当前任务 UUID，不累加过往运行时间。

日志以 JSONL 存储，每行一个结构化事件。内容不记录 Cookie 或代理密码。桌面客户端将数据写入 Electron `userData` 目录；从源码运行 Web/CLI 时使用项目内的以下目录：

| 路径 | 内容 |
| --- | --- |
| `data/*.json` | 用户来源或单曲分片检查点 |
| `data/*.jsonl` | 命中评论，按 `commentId` 去重 |
| `data/web-song-coverage-<UID>-target-v3.json` | GUI 的 UID 级完整歌曲覆盖账本 |
| `data/logs/<mode>-<uuid>.jsonl` | 任务调试日志 |
| `data/qq/state-<task-key>.json` | QQ 独立 SeqNo 扫描状态 |
| `data/qq/comments-<task-key>.jsonl` | QQ 命中结果，按 `(songId, commentId)` 去重 |
| `data/logs/qq-<uuid>.jsonl` | QQ 任务结构化日志 |
| `data/resume-task.json` | 最近一次 GUI 任务的私有恢复参数（含 canonical 目标，不应分享或写入日志） |
| `.ncm/cookie.txt` | 二维码登录会话 |
| `.ncm/proxy-pool.json` | 当前代理池状态与验证结果 |

这些路径都不应提交到 Git。

### 更新时如何保留扫描进度

Windows 客户端下载完更新后，如果扫描仍在运行，“重启并安装”会变为“保存进度并重启”。客户端通过全局任务协调器停止真实活跃的网易云或 QQ 任务，等待状态离开运行/停止中并完成强制检查点，再交给安装器重启；45 秒内无法确认时会取消安装，避免带着不确定状态退出。任务仍在启动或 QQ 歌曲查询尚未结束时也不会直接安装。
如果此时正在构建或复测代理池，更新会保持全局屏障并提示等待，不会绕过代理池租约强制终止 Mihomo；取消安装后屏障会释放。

普通顶部“停止”和应用退出使用同一全局任务事实源：即使当前切换到了另一个平台或模式，也会停止真实活跃的扫描，并等待其 Lease 与终态检查点结算；界面不会仅根据当前可见表单猜测任务。

任务参数和扫描状态都保存在 Electron 的同一个 `userData` 目录，不随应用版本替换。新版启动后会回填上次平台、模式、目标、歌曲 ID 与并行参数，但不会自动开始；保持“新建状态”关闭并再次开始，即可从相同检查点继续。当前恢复描述符为 v3，并带 `requestIntervalSemantics:"per-start-v1"`。旧 QQ 恢复参数若保存了大于 25 的评论页大小，会在任何远端请求前归一为 25；旧网易云间隔会按历史 Worker 数等价换算。两者都会显示 adjustment 提示，且不修改扫描检查点。极端退出情况下可能重复少量尚未确认的在途页面，结果 writer 会按各平台的稳定键去重。

target-v3 是一次显式安全边界升级：GUI 的 `record`、`likes`、`playlists`、`both` 与 `all` 都使用 `web-state-<UID>-<source>[-record-<scope>]-target-v3.json`，并共享受 owner 隔离的 `web-comments-<UID>-target-v3.jsonl` 与 `web-song-coverage-<UID>-target-v3.json`。非默认排行范围使用独立状态路径。早期版本曾把一个周榜状态写到无范围后缀的路径；新版只在共享文件锁内迁移 UID、来源和 `recordScope=week` 都精确匹配的文档，先原子建立或保留正确 scoped 状态并回读验证，再删除冲突旧文件及其专属恢复文件。目标身份冲突时会保留旧文件并报错。新版不会静默导入 target-v2 的 likes/both 文件，也不会把可能混入旧来源的未版本化 record 共享文件当作可信覆盖。CLI 默认路径同样带 target-v3 后缀，也可通过 `--state` / `--output` / `--coverage` 显式选择路径。

## 分页与检查点语义

- 歌曲评论使用 `comment_new` 降序时间游标，默认每页 1000 条，可配置范围为 `1..2000`。
- `hasMore=true` 时，下一游标必须严格向过去推进。空页但游标有效时会继续；游标缺失或不前进时保留可续跑状态，不会误报完成。
- 修改每页条数后不能直接恢复旧游标；请勾选“新建状态”或使用 `--fresh`。
- 用户来源检查点当前为 version 3，会持久化每首歌的未完成时间分片和最近一次目录对账统计；底层加载器仍能读取 version 1/2 的显式指定断点，但 GUI/CLI 的 target-v3 默认路径不会自动探测旧文件。GUI 代理池并行或 CLI 串行入口都能按 songId 保留分片状态。
- 从旧 `comment_music` offset 检查点迁移时，已完成歌曲保留，未完成歌曲从任务创建时间重扫，JSONL 继续去重。
- QQ 评论页使用十进制 SeqNo 游标，范围 `1..25`、默认 25；页内相等或局部乱序会保留全部评论并继续使用服务端原始末条 SeqNo，跨请求时整页所有 SeqNo 必须严格老于请求游标。无法安全推进的异常只隔离当前歌曲并保留原检查点，喜欢列表里的其他歌曲继续；公开喜欢来源页是独立接口，范围 `1..500`、默认 500。
- QQ 结果必须先完成 `write + fsync`，随后再次检查取消状态，最后才提交 seen key、页码和 cursor；停止、持久化失败或截断都不能误报完整覆盖。

## CLI

需要 Node.js 20 或更高版本：

```powershell
npm install
npm run build
```

常用命令：

```powershell
# 本地 Web 控制台：http://127.0.0.1:4173
npm run web

# 二维码登录
npm run start -- auth-qr

# 只收集候选歌曲，不读取评论
npm run start -- scan --uid 123456789 --source both --dry-run

# 扫描听歌排行 + 喜欢歌曲
npm run start -- scan --uid 123456789 --source both

# 扫描自建公开歌单，或合并全部来源；排行可同时读取全部时间与最近一周
npm run start -- scan --uid 123456789 --source playlists
npm run start -- scan --uid 123456789 --source all --record-scope both

# 已知歌曲 ID：有可用代理池时使用它，否则 CLI 会直连
npm run start -- scan-song --uid 123456789 --song-id 186016

# QQ CLI 当前是独立源码入口：解析用户、扫描单曲、扫描公开喜欢
npx tsx src/qq-cli.ts resolve-user --user 123456789
npx tsx src/qq-cli.ts scan-song --user 123456789 --song-id 102065756
npx tsx src/qq-cli.ts scan-likes --user 123456789 --max-songs 20
```

CLI `scan` 的默认单次请求预算为 250，`scan-song` 为 5000；达到预算后保存检查点并返回 `paused`。GUI 默认预算为 `0`，表示不因本地预算自动暂停。请求预算是评论页的逻辑调度限制，来源发现、歌曲详情和内部重试可能带来额外远端尝试，不应把它视为所有 HTTP 尝试的绝对硬上限。

查看全部参数：

```powershell
npm run start -- --help
```

## 代码结构

| 模块 | 职责 |
| --- | --- |
| `src/api.ts` | 网易云请求适配、响应归一化和加解密底座 |
| `src/scanner.ts` | 排行/喜欢/自建公开歌单收集、来源证据合并、多 Lane 页级调度和断点恢复 |
| `src/parallel-scanner.ts` | 单曲时间分片、自适应尾部拆分、页级队列和出口故障转移 |
| `src/qq-music/` | QQ Client、SeqNo Scanner、状态/结果 writer、代理 fetch、TransportGate 与 benchmark 模型 |
| `src/qq-job-manager.ts` | QQ Dashboard 应用层、generation、路径、代理 Lane、日志、结算与报告快照 |
| `src/qq-cli.ts` | 独立 QQ 命令行入口，不复制 Dashboard manager |
| `src/time-shards.ts` | 两种扫描器共用的半开时间分片创建与拆分规则 |
| `src/worker-topology.ts` | 计算受主机硬上限约束的实际 Worker 数 |
| `src/lane-allocator.ts` | 在全部健康出口间公平分配 permit，并守住每出口并发上限 |
| `src/song-metadata.ts` | 对来源目录和旧检查点中缺失的歌曲名称做有界批量补全 |
| `src/proxy-lane-selection.ts` | 自动模式保留全部已验证出口，或按手动上限裁剪出口集合 |
| `src/clash-profile-merge.ts` | Clash 配置校验、多配置公平候选、节点去重和重名处理 |
| `src/work-queue.ts` | 可等待重新入队的异步工作队列，避免 Worker 过早退出 |
| `src/cursor-pagination.ts` | 两种扫描器共用的降序游标推进规则 |
| `src/checkpoint-coordinator.ts` | 多 Lane 扫描共用的实时状态节流、不可变快照和串行检查点写入 |
| `src/task-coordinator.ts` | 全局单任务租约、代理池互斥与耗时计算 |
| `src/task-log.ts` | 按任务 UUID 串行写入结构化调试日志 |
| `src/result-accumulator.ts` | 统一 JSONL 去重后的检查点命中 ID 与计数更新 |
| `src/page-performance.ts` | 汇总真实评论页耗时、页填充与最终成功率，供运行中速度估算校准 |
| `src/jsonl-snapshot.ts` | 按导出开始时的固定字节边界读取完整追加式结果文件 |
| `src/result-report.ts` | 生成安全、可打印、支持中文和长评论跨页的 A4 结果报告 |
| `src/mihomo-pool.ts` | Clash Verge 发现、Mihomo 生命周期、网段去重与连通验证 |
| `src/server.ts` | 本地 API、任务/登录/代理池编排和结算快照 |
| `src/electron-main.ts` | 桌面窗口、内置服务生命周期、运行目录隔离与沙箱 PDF 打印 |
| `src/windows-updater.ts` | Windows 更新检查、下载、校验和重启安装状态机 |
| `web/` | 本地操作界面、实时结果、日志和结算画面 |

项目不使用数据库。评论结果是追加写入的 JSONL，扫描状态是 JSON，实时 UI 失败不得中断结果持久化。客户端启动扫描时会流式读取历史 JSONL 并定期让出事件循环，避免大结果文件造成窗口卡顿。实时结果按搜索发现顺序展示（最新发现优先），不会再按评论发布时间重排。喜欢来源通过目标 UID 所属的 `specialType=5` 歌单详情读取 `trackIds`，而不是直接使用可能被登录态覆盖身份的 `likelist`；只返回 ID 时会在后端批量补全歌曲名称并写入检查点。底层依赖固定为 `@neteasecloudmusicapienhanced/api@4.39.0`，避免上游变更直接影响正在续跑的任务。

自动化测试使用内存 API 桩和回环代理，不会默认向网易云或 QQ 音乐发送真实扫描请求。QQ CGI 并非稳定公开 SDK，实网只能做低频兼容性观察，不能替代确定性测试。
